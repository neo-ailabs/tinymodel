# Rockchip RK3588 / RK3588S 设备档案与分析

> 日期：2026-11-20  
> 固定参考设备之一（见 [AGENTS.md](../../AGENTS.md) §8），代表高性能国产 ARM Linux 边缘计算板（Orange Pi 5 / 5 Plus、Radxa Rock 5B、FriendlyElec NanoPC-T6、LubanCat-4 等）。  
> ⚠️ 本文 RK3588 的吞吐、延迟与功耗数据均为**基于硬件规格的理论推算**，待连上 RK3588 开发板跑 `bench/device_harness.py` 后替换为真机实测值。

---

## 1. 硬件规格与核心定位（对比 Pi 5 与 Pixel 8）

RK3588 在 `tinymodel` 的 `edge` 档位中处于 **“与 Pi 5 同代大核微架构（Cortex-A76），但内存带宽翻倍、内存上限高达 32 GB、且自带独立 Mali GPU 与 6 TOPS NPU”** 的甜点位置：

| 维度 | Raspberry Pi 5 | **Rockchip RK3588（RK3588S）** | Google Pixel 8（真机已测） |
|---|---|---|---|
| **制程** | TSMC 16nm | **Samsung 8nm LP**（能效显著优于 Pi 5） | Samsung 4nm |
| **CPU 拓扑** | 4× Cortex-A76 @ 2.4 GHz（同构） | **4× Cortex-A76 @ 2.25–2.4 GHz + 4× Cortex-A55 @ 1.8 GHz**（8 核异构 DSU） | 1× X3 @ 2.91G + 4× A715 @ 2.37G + 4× A510 @ 1.70G |
| **缓存层级** | 64KB L1 + 512KB L2/核 + 2MB L3 | **A76 512KB L2/核 + A55 128KB L2/核 + 3 MB 共享 L3** | 8 MB 共享 L3 + SLC |
| **ISA 指令集** | ARMv8.2-A：NEON + **`dotprod`** + FP16 算术（❌ 无 `i8mm`） | **ARMv8.2-A：NEON + `dotprod` (`sdot`) + FP16 算术 + LSE**（❌ **无 `i8mm`**） | ARMv9.0-A：NEON + `dotprod` + **`i8mm`** + FP16 |
| **内存规格** | 4 / 8 / 16 GB 32-bit LPDDR4X-4267 | **4 / 8 / 16 / 32 GB 64-bit 四通道 LPDDR4X-4266 / LPDDR5-4800** | 8 GB LPDDR5X |
| **持续内存读带宽** | ~11.5 GB/s | **~17 – 23 GB/s**（64-bit 总线理论峰值 34.1–38.4 GB/s；RK3588S 略低） | 实测 **31.1 GB/s**（`4×A715` STREAM Read） |
| **GPU** | VideoCore VII | **Arm Mali-G610 MP4**（支持 Vulkan 1.2/1.3、OpenCL 2.2） | Arm Mali-G715 MC7（Vulkan 1.3） |
| **NPU** | 无 | **内置 RKNPU2（3 核共 6 TOPS INT8，支持 INT4/INT8/FP16 混合）** | Tensor G3 TPU（锁死 AICore，第三方不可用） |
| **存储扩展** | PCIe 2.0 ×1 | **PCIe 3.0 ×4 NVMe SSD（顺序读高达 ~3.2 GB/s！）** + eMMC 5.1 | UFS 4.0（>2 GB/s） |

## 2. `tinymodel` 在 RK3588 上的适配与三大运行后端分析

### 2.1 CPU 路径（开箱即用，异构大小核策略已自动支持）
1. **ISA 自动选择**：`tm-cpu` 的 [isa.rs](../../crates/tm-cpu/src/isa.rs) 通过 `AT_HWCAP` 自动命中 **`Isa::NeonDotprod`**（`sdot` 4×8 点积内核）。注意 A76 和 A55 均支持 `dotprod`，不会出现跨核非法指令。
2. **大小核陷阱（A55 拖慢屏障——已在 Pixel 8 真机复现验证！）**：
   - 4 颗顺序执行小核 `Cortex-A55`（通常为 `cpu0..3`，掩码 `0x0f`）单核吞吐不到乱序大核 `Cortex-A76`（通常为 `cpu4..7`，掩码 `0xf0`）的 **1/4**。
   - 若直接跑 `-t 8` 全核均分，4 个 A76 算完会空转等待 A55！
   - **已内置自动处理**：[probe.rs](../../crates/tm-cli/src/probe.rs) 已内置 `0xd0b -> Cortex-A76` 与 `0xd05 -> Cortex-A55` 识别，[device_harness.py](../../bench/device_harness.py) 的默认 `--cluster-policy no-little` 会**自动生成 `taskset f0 -t 4` 只绑 4 个 A76 大核**（在极致需要榨干最后 ~15% 带宽时，后续配合动态细粒度分块可尝试 4×A76 + 2×A55）。
3. **系统内核与存储**：主流 Armbian / Joshua-Riek Ubuntu 22.04/24.04（Linux 6.1 BSP 或 6.8+ 主线内核）均完美兼容 `aarch64-unknown-linux-musl` 纯静态二进制；搭配 PCIe 3.0 NVMe SSD 时，冷启动缺页读 `4.7 GiB` 8B 模型仅需 **~1.5 秒**。

### 2.2 Mali-G610 MP4 Vulkan GPU 路径（对应 M3 阶段）
- **为什么 RK3588 的 Vulkan 比树莓派更有价值**：
  1. Mali-G610 MP4 算力约 **450–610 GFLOPS（FP16）**，是 4 核 Cortex-A76 CPU 浮点算力的 **2.5×–3×**，对算力受限的 **Prefill（TTFT）与端侧 QLoRA 微调** 有明显加速；
  2. 在许多 RK3588 BSP 内核上，单靠 4 个 A76 大核只能跑到约 `17–19 GB/s` 内存读带宽，而 Mali-G610 GPU 或 CPU+GPU 并发能进一步推高对 64-bit LPDDR4X/5 控制器的带宽占用率。
- **驱动注意事项**：
  - Linux 6.10+ 主线 Mesa **Panthor** 开源驱动已原生支持 Mali-G610（Vulkan **PanVK** 正快速成熟）；厂商 6.1 BSP 内核则通过 Arm 闭源 `libmali-valhall-g610` 提供 Vulkan 1.2。编写 `tm-vulkan`（M3）时需检测 Subgroup 大小（Mali Valhall 为 **16 wide warp**，不同于 NVIDIA 的 32 和 AMD 的 64！）。

### 2.3 内置 6 TOPS RKNPU2（对应 M6 实验阶段：`rkllm` 对比）
- 瑞芯微官方闭源 `rkllm-runtime` 可利用 3 核 NPU 跑 `W4A16` / `W8A8` 模型，**优势在于极低 CPU 占用与极高能效（整板功耗仅 ~4–5W）**。
- 但 RKNPU2 也有明显短板：① 闭源编译器只支持主流旧结构，**不支持 Qwen3.5 GDN、Gemma 4 PLE 等最新混合结构**；② 受限于同一条 LPDDR4X 总线带宽，NPU 在 Decode 阶段的速度（0.8B 约 `25–30 tok/s`，2B 约 `11–13 tok/s`）与高度优化的 CPU `dotprod` + Vulkan 差距并不悬殊，主要赢在 **Prefill 吞吐（可达 200–350 tok/s）与功耗**。因此 `tinymodel` 在 M1–M3 主打 **CPU `dotprod` + Mali Vulkan**（通吃所有新模型结构），M6 再探索把线性投影卸载到 RKNPU。

## 3. 四大维度量化评估（推理、TTFT、微调、功耗）

> 全部为理论推算（按有效内存读带宽 `15–18 GB/s`、4×A76 `dotprod` / FP16 算力折算）：

### 3.1 推理吞吐与模型上限
得益于可选 **16 GB / 32 GB 内存**与 **PCIe 3.0 NVMe**，RK3588 是唯一能从容运行 **7B–9B 模型**（甚至驻留多个模型）的 `edge` 级低功耗开发板：

| 模型（Q4_0） | 权重体积 | **RK3588（4×A76 CPU 估算）** | RK3588（+Mali Vulkan 预估） | Pi 5（估算） | Pixel 8（真机实测 `0x1f0`） |
|---|---:|---:|---:|---:|---:|
| `SmolLM2-360M` | 219 MiB | **55 – 70 tok/s** | ~75 – 90 tok/s | 35 – 45 tok/s | **~75+ tok/s**（`0xf0` 实测 65.5） |
| `Qwen3.5-0.8B` | 484 MiB | **24 – 31 tok/s** | ~32 – 38 tok/s | 15 – 20 tok/s | **36.4 tok/s**（实测！） |
| `Qwen3.5-2B` | 1.13 GiB | **11 – 14 tok/s** | ~15 – 18 tok/s | 6 – 8 tok/s | 见最新实测 |
| `Qwen3.5-4B` / `Gemma 4 E4B` | ~2.4 GiB | **5.5 – 7.0 tok/s**（8GB+ 板） | ~7.5 – 9.0 tok/s | 3 – 4 tok/s | 受 8GB 手机可用内存限制 |
| `Llama-3.1-8B` / `Qwen3.5-9B` | ~4.7 GiB | **2.8 – 3.6 tok/s**（16G/32G 板） | ~4.0 – 4.8 tok/s | 16G 板勉强 ~1.8 tok/s | 8GB 板装不下 |

### 3.2 首字延迟（TTFT）
- **292 token prompt（`Qwen3.5-0.8B`）**：纯 4×A76 CPU（无 `i8mm`，走 `dotprod`）Prefill 估算 **`65 – 95 tok/s`**，对应 TTFT 约 **`3.1 – 4.5 秒`**；未来接上 M3 **Mali-G610 Vulkan FP16 GEMM** 后预计可提至 **`180 – 260 tok/s`（TTFT 压至 `1.1 – 1.6 秒`）**。
- **NVMe 冷启动优势**：配合 PCIe 3.0 ×4 SSD（`~3 GB/s`），即便系统刚重启、页缓存全空，首次 `mmap` 读取 `Qwen3.5-2B` 也仅增加 **~0.4 秒** I/O 延迟（对比 MicroSD 卡需 15–25 秒）。
- 同样最受益于 **F-13 前缀缓存 + 状态快照落盘**（将多轮/固定系统提示 TTFT 压至几毫秒）。

### 3.3 端侧微调（QLoRA，$T=512$, $r=8$）
- **CPU 算力**：4×A76 @ 2.4 GHz FP32 峰值约 `153 GFLOPS`（有效 `60–80 GFLOPS`），支持 **ARMv8.2 FP16 算术**（约 `300 GFLOPS` 峰值）。
- **Mali-G610 MP4 GPU 算力**：FP16 峰值约 **`450–610 GFLOPS`**——一旦在 M3/T3 接通 Vulkan 反向矩阵乘，RK3588 的微调速度可达 Pi 5 的 **2.5×–3.5×**！
- **大内存不可替代性**：**16 GB / 32 GB 版 RK3588** 可以把 **4B 甚至 8B 模型**连同激活检查点全部常驻物理内存不触发 Swap，并可加小散热风扇 **7×24 小时不降频挂机微调**（完全没有手机的温控和后台杀进程限制）：
  - `Qwen3.5-0.8B`：纯 CPU 约 **`16 – 26 tok/s`**；接 Mali Vulkan 后预估 **`45 – 75 tok/s`**（10 万 token 个性化微调约 **25–35 分钟**）。
  - `Qwen3.5-2B`（8GB+ 板）：纯 CPU 约 **`6 – 10 tok/s`**；Mali Vulkan 预估 **`18 – 30 tok/s`**。

### 3.4 功耗与能效（J/token）
- **8nm 制程红利**：4×A76 满载跑推理时，RK3588 SoC 功耗约 **`4.5 – 6.5 W`**（整板约 `6 – 8.5 W`，低于 16nm 的 Pi 5，且带宽高近一倍），因此 **每 token 能耗（J/token）比 Pi 5 低约 40%–55%**（0.8B 估算约 **`0.20 – 0.28 J/token`**）。
- **省电调优建议**：
  1. **严格屏蔽 4×A55 小核**（`--cluster-policy no-little` / `taskset f0 -t 4`），避免大核自旋空等小核白烧电；
  2. Decode 阶段将 `policy4`（A76 簇）调频器设为 `schedutil` 或限频至 `1.8–2.0 GHz`（避开 `2.4 GHz` 高压低效区，带宽几乎不掉而 CPU 功耗省 ~25%）；
  3. 远期重度能效场景（电池供电机器人/无人机）可在 M3 用 Mali Vulkan 或 M6 调用 RKNPU2（可将 0.8B 能效进一步压至 `~0.12–0.15 J/token`）。
- **功耗测量方式**：部分 RK3588 开发板（如 Rock 5B / ITX）带 USB-C PD 芯片可从 `/sys/class/power_supply/tcpm-*` 读电压电流，其余板卡用 USB-C / DC 串联功率计测整板功率。

## 4. 连接 RK3588 后的实测命令
RK3588 接入局域网（或通过 Type-C OTG 虚拟网卡连接主机）后，直接调用已实现的统一测试接口即可一键交叉编译、识别 `4×A76 + 4×A55`、自动绑 `0xf0` 大核并产出基准报告：

```sh
python3 bench/device_harness.py probe --target ssh://root@<rk3588-ip> --build
python3 bench/device_harness.py run --target ssh://root@<rk3588-ip> \
    -m models/SmolLM2-360M-Instruct-Q4_0.gguf \
    -m models/Qwen3.5-0.8B-Q4_0.gguf \
    -m models/Qwen3.5-2B-Q4_0.gguf \
    --cluster-policy no-little --reps 5 --compare-local
```
