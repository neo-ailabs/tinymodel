# 路线图（Roadmap）

> 每个阶段都有可量化的验收标准。基线以同一台机器上的 llama.cpp 为准（见 `TESTING.md` 的基准协议）。

| 阶段 | 内容 | 验收标准 | 状态 |
|---|---|---|---|
| **M0 基线** | 在 M4 和 Pi 5 上用 llama.cpp 测量基准模型集的 pp、tg、内存峰值、温度和频率 | 有可复现的基线表格，存入 `bench/baselines/` | 🟡 M4 已完成（2026-11-19），Pi 5 待测 |
| **PoC** | ① 用 Rust 写 Q4_0×Q8_0 GEMV（NEON dotprod + i8mm `asm!`），以 `Strata/src/quant/arm/arm_dots.inc` 为蓝本；② 交叉编译 aarch64-musl，在 Pi 5 和 Zero 2W 上运行；③ objc2-metal 量化 GEMV；④ 内核对齐和 bench 测试框架 | ① 在 M4 上 ≥95% ggml；② 二进制 <2MB，Pi 5 带宽利用率 ≥80%；③ ≥90% llama.cpp Metal | 🟡 M4 + **Google Pixel 8 真机验证通过**（2026-11-20：877KB 静态 `aarch64-musl` 在 Tensor G3 真机通过 L1 自检，`Llama-1B` 带宽利用率 **90.9%**，`SmolLM2` 达 **83.6–90.0 tok/s**），Pi 5 / Zero 2W 待跑 |
| **M1 最小可用** | Cargo workspace 骨架；tm-core / tm-gguf（张量表校验）/ tm-cpu（generic + NEON + dotprod + AVX2）/ 线程池；Llama + Qwen3 的 forward；tokenizer；采样；CLI `run` / `bench` | 贪心解码输出和 llama.cpp 逐 token 一致；Pi 5 decode ≥95% llama.cpp | 🟡 M4 上 Llama/Qwen3 + 采样器 + NEON F16 KV / 4×8 `smmla` 完成（2026-11-20：SmolLM2 `pp512=588.8 / tg128=270.5 tok/s` [= **106.3%** llama.cpp `--no-repack` / **116.1%** 默认]，Llama-1B `pp512=246.6 / tg128=84.9 tok/s` [= **96.4%** llama.cpp]，micro 静态二进制 668KB），Pi 5 实测待跑 |
| **M2 新结构 + Metal** | Qwen3.5（GDN，按 `GDN_CONTRACT` 实现）、Gemma 4（PLE、滑动窗口）、LFM2；LayerState；前缀缓存；**Metal 后端** | 多 token logits 的 KL 低于阈值；M4 Metal decode ≥90% llama.cpp Metal | ✅ **已完成**（2026-11-21：① CPU + Metal 全量支持 `Qwen3.5`、`Gemma 4`［PLE 按需单行 mmap、`BF16` 模型投影、4:1 SWA/比例 RoPE、20 层共享 KV、GeGLU、softcap、`gemma4` SPM-BPE］与 `LFM2`［门控 `ShortConv` + QK-Norm GQA］；② 多 token `logits_diff.py` 全部通过：`Gemma 4 E2B` Metal vs `llama.cpp` 38 步 `Top-1=100% / mean_KL=1.70e-7`、CPU `Top-1=94.7% / mean_KL=2.15e-3`，`LFM2` 61 步 `Top-1=100% / mean_KL=8.23e-10 (Metal) & 2.57e-7 (CPU)`；③ **M4 Metal decode 全面 ≥90% `llama.cpp Metal`**：`Qwen3.5-0.8B` **99.5%**［`129.0 tok/s`］、`Qwen3.5-2B` **96.1%**［`63.3 tok/s`］、`Gemma 4 E2B` **95.0%**［`52.3 tok/s`］、`Llama-3.2-1B` **94.5%**［`108.8 tok/s`］；④ `tm-runtime` 统一 `Session` + 内存受限 LRU `PrefixCache`［KV/SWA 任意前缀截断 + GDN/ShortConv 递归检查点逐位无损恢复］；⑤ **Pixel 8 真机实测 `Gemma 4 E2B`**：`pp512=121.9 tok/s`［**118.0%** `llama.cpp --repack 0`］、`tg64=14.56 tok/s`［**99.7%**］，总 RSS 仅 `1.47 GiB`、脏内存仅 `55.6 MiB`） |
| **M3 性能** | prefill GEMM 微内核；suffix 和 MTP 投机解码 + 按收益选择；多 token 共享权重；LM head 优化；KV 量化；**Vulkan 后端**（覆盖 AMD、Intel 显卡、Mali、Pi 5 VideoCore） | Pi 5 prefill ≥1.5× llama.cpp，有效 decode ≥1.3× | 🟡 **异构大小核自动绑核（`affinity.rs`）+ Prefill 非矩阵算子并行化（GDN Conv1d/Recurrence、SwiGLU、批量 GQA）已完成**（2026-11-21：Pixel 8 免 `taskset` 开箱提速 **3.3×–5.0×**，`Llama-3.2-1B` Prefill 达 **106.9%** `llama.cpp --repack 0`）；`Q4_0_4x8` 离线重排 / 投机解码 / Vulkan 待做 |
| **M4 micro 档** | ARMv8.0 NEON 和 TBL 查表内核；低比特格式（IQ2/3、Q2_0、三值）；词表裁剪；零拷贝 | Zero 2W 上 SmolLM2-360M Q4 ≥5 tok/s，内存 ≤350MB | 🟡 **ARMv8.0 NEON 全套量化内核（Q4_0/Q4_1/Q8_0/Q5_K/Q6_K）+ GGUF 零拷贝词表 + 扁平 Tokenizer + Linux cgroup v2 内存探测已完成**（2026-11-20：SmolLM2-360M `Isa::NeonV80` 提速 **+44.3%**、脏内存仅 **25.3 MiB** / 总 RSS **248 MiB**；Qwen3.5-0.8B 脏内存省 **87.2 MiB** 至 **51.8 MiB**；`micro` 纯静态 ELF **745KB** 零 `sdot`/`smmla`）；低比特格式 / TBL 待做 |
| **M5 服务与生态** | OpenAI 兼容服务（tool calling、模板）；C ABI；Python 绑定；**CUDA 后端**；分页 KV；并发 | 工具调用语料切片测试全部通过 | ⬜ |
| **M6 扩展** | 多模态编码器；小型 MoE；Mamba2；NPU 实验（Hailo / RKNPU） | — | ⬜ |
